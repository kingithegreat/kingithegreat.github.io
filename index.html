How I work

Three habits

Test the logic, play the game

Core rules get unit tests with no framework dependencies, so they run anywhere in a second. But I've learned the hard way that green tests don't mean it works — someone still has to open the thing and use it.

Automate the boring half

Every repository builds, tests and deploys itself on push. If a step is manual it eventually gets skipped, and the step that gets skipped is the one that breaks production.

Small changes, often

I work in short branches and merge quickly. It keeps reviews readable, makes problems easy to trace to a single change, and means progress is always visible.
